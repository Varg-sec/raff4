# Demonstrate a generated binding for another language

Local ID: AFF4-023

Type: HITL · Area: optional

## What to build

After the Rust core release candidate is ready, validate the library boundary with one additional language selected by the maintainer. This is deferred work.

## Acceptance criteria

- [ ] Choose a target language and evaluate UniFFI versus a C ABI with generated headers against that language’s tooling.
- [ ] Build a small external consumer that opens a fixture, reads bytes and receives a structured error.
- [ ] Specify ownership, buffer lifetimes, threading and ABI stability; exercise close and failure paths.
- [ ] Keep format logic in the Rust core and document generation commands and unsupported API features.

## Blocked by

- AFF4-022

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. The initial implementation and acceptance tests are Rust-only. Python bindings are deferred to AFF4-024 after the Rust core release candidate.
