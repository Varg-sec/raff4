# Read multipart container sets

Local ID: AFF4-016

Type: AFK · Area: multipart

## What to build

Open an explicitly supplied collection of volumes as one evidence image from Rust.

## Acceptance criteria

- [ ] Resolve objects and ranges across volumes using identity and metadata; filenames are discovery hints only.
- [ ] Test reordered inputs, duplicate volumes, missing members, foreign members and names with multi-digit suffixes.
- [ ] Read across a volume boundary and report missing members precisely without claiming complete verification.
- [ ] Bound file-handle use and allow caller-controlled discovery without arbitrary filesystem traversal.

## Blocked by

- AFF4-011

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. The initial implementation and acceptance tests are Rust-only. Python bindings are deferred to AFF4-024 after the Rust core release candidate.
