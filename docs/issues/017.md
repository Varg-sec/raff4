# Write multipart physical and logical containers

Local ID: AFF4-017

Type: AFK · Area: multipart

## What to build

Split output at a caller-specified volume size and reopen the resulting set as one image.

## Acceptance criteria

- [ ] Write consistent member identities, links, naming and per-volume metadata with correct finalization.
- [ ] Round-trip physical and logical data crossing split boundaries from both languages.
- [ ] Verify hashes across the set and detect incomplete output after simulated I/O failure.
- [ ] Document unavoidable size overhead and boundary behavior; independently inspect generated members.

## Blocked by

- AFF4-015
- AFF4-016

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. Bindings must delegate format behavior to the Rust core.
