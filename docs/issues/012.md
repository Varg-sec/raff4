# Verify logical content and metadata integrity

Local ID: AFF4-012

Type: AFK · Area: integrity

## What to build

Extend verification to logical files and metadata, reporting integrity coverage per object and store.

## Acceptance criteria

- [ ] Check primary metadata bytes and all required file/map digests using the pinned AFF4-L profile.
- [ ] Support required digest aliases and new algorithms as determined by the baseline; test SHAKE lengths explicitly.
- [ ] Detect altered names, inline bytes, stored file data and digests independently; document that hashes alone do not authenticate provenance.
- [ ] Expose identical structured coverage and failure results in Rust.

## Blocked by

- AFF4-006
- AFF4-010
- AFF4-011

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. The initial implementation and acceptance tests are Rust-only. Python bindings are deferred to AFF4-024 after the Rust core release candidate.
