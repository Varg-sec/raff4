# Write and reopen an uncompressed physical image

Local ID: AFF4-007

Type: AFK · Area: writer

## What to build

Stream caller-supplied bytes into a new AFF4 physical container and reopen it using either public API.

## Acceptance criteria

- [ ] Emit valid volume metadata, indexes and hashes; finalize explicitly and surface all flush/close errors.
- [ ] Round-trip empty, partial-chunk, multi-bevy and ZIP64 boundary cases with bounded buffering.
- [ ] Accept Rust readers and Python byte streams without requiring full input in memory.
- [ ] Verify produced output with this library and an independently pinned reader; interrupted writes are not reported as complete.

## Blocked by

- AFF4-003
- AFF4-006

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. Bindings must delegate format behavior to the Rust core.
