# Add optional metadata signing and trust evaluation

Local ID: AFF4-020

Type: HITL · Area: optional

## What to build

Allow applications to sign metadata and evaluate signatures using caller-supplied trust policy.

## Acceptance criteria

- [ ] Resolve the signature wire format and interoperability fixtures with a maintainer before implementation; PEM alone is not a complete signature specification.
- [ ] Round-trip signatures and certificate chains, including multiple signers, through Rust and Python.
- [ ] Distinguish valid signature, trusted signer, expired/revoked certificate, unsupported scheme and unverifiable trust.
- [ ] Keep keys and network trust lookup under application control; mutation and wrong-key tests must fail.

## Blocked by

- AFF4-012
- AFF4-018

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. Bindings must delegate format behavior to the Rust core.
