# Restructure the workspace into library and executable packages per the Cargo book layout

Local ID: AFF4-025

Type: AFK · Area: foundation

## What to build

Adopt the [project layout recommended by the Cargo book](https://doc.rust-lang.org/cargo/guide/project-layout.html): each package uses `src/lib.rs` or `src/main.rs` as its entry point, with `tests/`, `examples/` and (when first needed) `benches/` directories at the package root. Today the entire implementation lives in a single lib-only package (`crates/aff4`, package name `libaff4`, lib name `aff4`) whose only executable surface is the `examples/inspect.rs` example. That is not the layout the guide describes for a project with a library and a main executable, and the example binary is invisible to `cargo build` and `cargo install`. During delivery the library package is additionally renamed from `libaff4` to `aff4`, so package, library crate and import name all match.

Split the executable into its own package so the two projects are independent: a pure library package that has no binary and depends on nothing CLI-related, and a CLI package whose `src/main.rs` is the main executable and which depends on the library. The library stays embeddable and mandatory-CLI-free, as required by docs/design.md. A suggested target layout:

```text
.
├── Cargo.toml            # workspace root (members, shared lints, package metadata)
├── crates/
│   ├── aff4/             # library package: src/lib.rs, src/{container,metadata,...}.rs,
│   │                     # tests/, examples/ — no [[bin]] targets
│   └── aff4-cli/         # executable package: src/main.rs, depends on the aff4 library
└── ...
```

The exact package names are an implementation decision, subject to one constraint: the library's importable name (`aff4`) and its public API must not change, and the CLI package name must not shadow the library. Keep using `[workspace.package]` inheritance for `version`, `edition`, `rust-version` and `license`, and keep the shared `[workspace.lints]`. If `examples/inspect.rs` already covers the first executable's behavior, promote it into the CLI package rather than maintaining two entry points.

## Acceptance criteria

- [ ] The workspace contains two packages: a library package without any `[[bin]]` target and an executable package with `src/main.rs` as its main binary.
- [ ] Within each package, entry points and directories match the Cargo book layout (`src/lib.rs`, `src/main.rs`, `tests/`, `examples/`, `benches/` as applicable); no code remains at the previous location.
- [ ] `cargo build`, `cargo test`, `cargo run -p <cli>`, and `cargo install -p <cli>` work from the workspace root; the library builds and tests with no binary and no CLI dependency in its dependency graph.
- [ ] The public API (`aff4::{Container, ImageStream, Metadata, Error, ...}`), crate name and MSRV (1.85) are unchanged; existing unit, synthetic and canonical tests pass unmodified except for updated package references.
- [ ] The former example executable's functionality remains available as the CLI (or, if intentionally demoted, the decision and its reason are recorded).
- [ ] CI is updated: fmt/clippy/test invocations, the canonical-fixture job (`-p aff4 --test canonical`) and the MSRV job reference the new package names; every workflow invocation still selects an existing package or target.
- [ ] README, docs/design.md and docs/backlog.md describe the new layout; the design note that the core avoids a mandatory CLI still holds (the CLI is a separate optional package).

## Blocked by

None — but perform this restructuring before writer-track issues (AFF4-007 and later) add further code that would have to move again.

## Evidence and delivery

This is a pure structural refactor: no format behavior changes, no new capabilities, no fixture changes. Record the before/after layout in the delivery notes, run the full workspace gate (`cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`) plus the canonical regression, and update the conformance matrix only where it names paths. Python bindings (AFF4-024) and other-language bindings (AFF4-023) are unaffected; both continue to target the library package.
