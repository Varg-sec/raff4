# Verify physical image content and structural hashes

Local ID: AFF4-006

Type: AFK · Area: integrity

## What to build

Offer a verification report in Rust that identifies exactly what was checked and what failed.

## Acceptance criteria

- [ ] Implement the pinned base hash constructions for linear content, blocks, maps, indexes and aggregate image integrity.
- [ ] Cover each required algorithm with independent known-answer vectors and canonical images.
- [ ] Separate verified, mismatch, missing, unsupported and not-checked results; never report unsupported verification as success.
- [ ] Mutate data, indexes and expected digests independently and demonstrate localized failures; expose cancellation and progress for long runs.

## Blocked by

- AFF4-004
- AFF4-005

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. The initial implementation and acceptance tests are Rust-only. Python bindings are deferred to AFF4-024 after the Rust core release candidate.
