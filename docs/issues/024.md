# Add Python bindings after the Rust core is ready

Local ID: AFF4-024

Type: AFK · Area: bindings · Phase: deferred

## What to build

Once the Rust reader, writer and verifier have a tested release candidate, expose their supported capabilities through a separate PyO3 adapter and maturin package. All format behavior remains in the Rust core. Do not start this issue during the initial Rust implementation phase.

## Acceptance criteria

- [ ] Select supported Python versions and platform wheel targets when this phase starts.
- [ ] Expose container enumeration, typed metadata, incremental reads, seek, writes and verification using the tested Rust API.
- [ ] Implement ownership, explicit close and context managers; translate structured errors to Python exceptions and prevent panics crossing the boundary.
- [ ] Specify buffer lifetimes, thread behavior, cancellation and progress for long operations.
- [ ] Reuse the Rust core's independent fixture expectations in Python tests for every wrapped capability.
- [ ] Build and import wheels on the agreed platforms, generate and check type stubs, and document the Python API.
- [ ] Test installed wheels and keep the Rust library usable without Python or PyO3 dependencies.

## Blocked by

- AFF4-022

## Evidence and delivery

Python bindings were explicitly deferred by the maintainer on 2026-11-06. This issue collects the Python work previously distributed across the core issues. Optional format extensions can be wrapped after they are implemented in Rust. Package publication remains a separate release action.
