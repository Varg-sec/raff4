# Open a container and inspect its metadata from Rust and Python

Local ID: AFF4-002

Type: AFK · Area: reader

## What to build

Deliver the first complete consumer path: a Rust caller and an installed Python extension open a fixture, enumerate image identifiers and query typed metadata.

## Acceptance criteria

- [ ] Read ZIP/ZIP64 container identity, version and Turtle with profile-specific identifier mapping and typed RDF values; preserve unknown triples.
- [ ] Use a separate PyO3 adapter crate and maturin package; Python objects own their Rust handles and have explicit close/context-manager behavior.
- [ ] Expose structured Rust errors and stable Python exceptions for corrupt ZIP, invalid metadata and unsupported versions; no panic crosses the boundary.
- [ ] Build and import a wheel in CI and run the same fixture assertions in Rust and Python; the Rust core has no Python dependency.

## Blocked by

- AFF4-001

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. Bindings must delegate format behavior to the Rust core.
