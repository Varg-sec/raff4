# Open a container and inspect its metadata from Rust

Local ID: AFF4-002

Type: AFK · Area: reader

## What to build

Deliver the first complete consumer path: a Rust caller opens a fixture, enumerates image identifiers and queries typed metadata.

## Acceptance criteria

- [ ] Read ZIP/ZIP64 container identity, version and Turtle with profile-specific identifier mapping and typed RDF values; preserve unknown triples.
- [ ] Expose owned container handles, typed metadata and explicit resource lifetime behavior through a documented Rust API.
- [ ] Expose structured Rust errors for corrupt ZIP, invalid metadata and unsupported versions; malformed inputs must not panic.
- [ ] Run fixture assertions through the public Rust API in CI; the library has no Python dependency.

## Blocked by

- AFF4-001

## Evidence and delivery

Use the pinned baseline established in AFF4-001 and the source index in docs/design.md. Add an end-to-end fixture demonstrating this capability, record unsupported cases, and update the conformance matrix. The initial implementation and acceptance tests are Rust-only. Python bindings are deferred to AFF4-024 after the Rust core release candidate.
